导读：这本教程讲什么

这是一本 Next.js 全栈架构最佳实践教程。它不讲某个 API 怎么调，而是讲一个全栈应用应该怎样组织：怎么分层、配置怎么管、数据怎么建模、认证怎么做、并发怎么控、外部服务怎么接、怎么测、怎么部署——这些决定一个项目能不能长期维护的架构问题。

教程贯穿一个完整的参考实现：一个用 Next.js 16 + PostgreSQL 构建的全栈应用（前台浏览、账号、购物车、结账支付、订单、运营后台一应俱全，源码在仓库 project/ 目录）。商城只是载体——每章讲的都是可以迁移到任何全栈项目（SaaS、内部系统、内容平台）的架构方法：

怎么用这本教程

  1. 先把参考实现跑起来（下一节），用演示账号把主要流程走一遍：浏览 → 加购 → 结账 → 后台发货 → 取消/退款。
  2. 按章节顺序读。每章的结构是：要解决的架构问题 → 看哪段代码 → 为什么这样设计 → 常见误区 → 练习。
  3. 练习一定要做。每章末尾的练习都是在真实代码上动手改，改完跑测试验证。架构直觉是改出来的，不是读出来的。

运行参考实现

只需要 Docker（含 Docker Compose），在 project/ 目录执行：

docker compose up --build

首次构建要几分钟（拉镜像、装依赖、建表、灌演示数据）。完成后打开 http://localhost:3000 。

账号 密码 角色
admin@example.com admin123 管理员（可进 /admin）
demo@example.com demo1234 顾客

没有配置 Stripe 时，结账会进入一个站内「模拟支付」页面，点击确认即可走完整个流程（第 12 章讲这个降级设计）。

停止：Ctrl+C；连数据一起清掉重来：docker compose down -v（注意：-v 会删掉数据库 volume，不可恢复）。

本地开发（不用 Docker）：cp .env.example .env.local，准备一个本地 PostgreSQL，然后 npm install && npm run db:setup && npm run dev；测试 npm test，类型检查 npm run typecheck。

阅读约定

  • 代码块上方标注了文件路径，以参考实现根目录为起点，例如 src/features/checkout/actions.ts。
  • 教程里的代码是节选，完整代码请对照仓库 project/ 目录看。
  • 每章末尾的「常见误区」同样重要：架构能力一半体现在知道什么不能做。

本章练习

  1. 把参考实现跑起来，用顾客账号完成一次下单，再用管理员账号发货。
  2. 打开 project/README.md 的项目结构图，先自己说出每个目录的职责，再对照第 1 章验证。
  3. 找到 README 里「上线前还需要」那一节——读完本教程后你应该能逐条说出每一条背后的原因。
