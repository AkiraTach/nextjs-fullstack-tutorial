# 第 16 章 对照总结与进阶路线

## 本章目标

- 把全书的两套选择汇总成一张对照表，形成自己的选型直觉
- 给出一条从「读懂」到「能改、能扩展」的进阶练习路线

## 16.1 全书对照表

| 主题 | 项目 A（NextShop） | 项目 B（Field Shop） | 选型依据 |
| --- | --- | --- | --- |
| 数据访问 | Drizzle ORM + 生成迁移 | 手写 SQL + 初始化脚本 | 长期维护选 ORM；学透 SQL 与事务选手写 |
| 会话 | JWT 无状态 | 令牌哈希 + 会话表 | 要即时撤销选 B；要无状态扩容选 A |
| 密码哈希 | 应用层 bcryptjs | 数据库 pgcrypto | 主流选应用层；B 胜在代码短 |
| 购物车 | 游客车 + 登录合并 | 登录用户 + 用户行锁 | 取决于游客能否加购这个业务决定 |
| 防超卖 | 条件 UPDATE | 行锁 FOR UPDATE | 都可；A 无锁更轻，B 锁内逻辑更直白 |
| 支付 | Stripe + webhook，可降级模拟 | 事务内模拟 | 生产形状看 A；教学简化看 B |
| 订单状态 | 4 态，action 内手写流转 | 6 态，状态机表 + workflow 收口 | 流转多、入口多时必须收口成表 |
| 定价 | 小计 only | domain 纯函数（含优惠/运费） | 规则一复杂就抽 domain |
| 缓存 | unstable_cache + tag 失效 | 不用，强制动态 | 公开数据才缓存；用户数据永不共享缓存 |
| 表单错误 | useActionState 字段级回显 | redirect 错误码 | 公众产品选前者；内部工具可选后者 |
| 测试 | Vitest（money/token/schemas） | node:test（totals/状态机） | 工具随意，选点一致：先测领域纯函数 |
| 部署 | 多阶段镜像 + migrate 独立服务 | 单阶段教学镜像 | 上线形状看 A |

把这张表读出一个规律：**两个项目的差异几乎都不是「谁对谁错」，而是「业务前提不同」或「复杂度不同」**。以后你做选型时，先写下前提，再选机制——顺序反了，就会拿着锤子找钉子。

## 16.2 共同的底线（两个项目都不妥协的事）

无论路线怎么不同，这些在两边都成立，可以当作你的默认清单：

1. 金额用最小单位整数；价格只信服务端。
2. 输入一律校验（Zod），数据库约束兜底（唯一、CHECK、NOT NULL）。
3. 每个写入口都重新验身份与权限；他人的资源按不存在处理（404）。
4. 下单类操作进事务；防超卖靠条件更新或行锁；重复提交靠幂等键 + 唯一约束。
5. 支付状态只认服务端可信通知（webhook），且处理必须幂等。
6. 订单存价格快照；状态变更与审计、库存恢复同事务。
7. 密钥运行时读取、生产强制校验；构建不依赖数据库与密钥。
8. 诚实地写下未做的事（两个项目的 README 都是范本）。

## 16.3 进阶练习路线（按顺序做）

**第一组：补齐缺口（在任一项目上）**
1. 登录限流：按邮箱 + IP 计数，N 次失败后冷却。用数据库表实现，写测试。
2. 未支付订单超时清理：给 A 的模拟支付订单加 30 分钟过期清理（定时任务调 `cancelOrderAndRestock`）。
3. outbox 投递器：给 B 写一个轮询 outbox 的 worker，先把事件打印到日志，再接一个本地邮件模拟服务。

**第二组：业务扩展**
4. 商品变体（SKU）：颜色/尺码如何建模？库存落在商品级还是 SKU 级？下单、购物车、快照要怎么跟着改——这道题会逼你重走第 3、10、11 章。
5. 图片上传：接 S3/R2 预签名直传，替换现在的图片 URL 文本框（注意校验与孤儿文件清理）。
6. 全文搜索：把 A 的 ILIKE 搜索换成 PostgreSQL 全文检索或 Meilisearch，对比相关性与运维成本。

**第三组：工程化**
7. Playwright E2E：覆盖「下单 → 支付 → 发货」主干，再加一条越权用例。
8. 并发集成测试：完成第 14 章练习 3，并把它接进 CI。
9. 把 B 的初始化 SQL 改造成版本化迁移（引入迁移表 + 编号脚本），让已有数据卷也能升级表结构。

## 16.4 最后的话

这两个项目加起来不到万行代码，但把全栈电商的硬骨头都摆在了明面上：钱、库存、权限、并发、支付。下次你自己从零搭一个系统时，先翻回第 16.2 节的底线清单逐条对照——能把这八条守住，你的系统就已经超过绝大多数「能跑就行」的实现。

教程中若有与代码不一致之处，以仓库 `projects/` 里的代码为准——代码是唯一的事实来源，这也是本教程从头到尾想教你的态度。
